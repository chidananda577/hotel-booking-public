## 1. Architecture Overview (Solution Architecture)
### Architecture Overview
A local-deployed, JWT-secured hotel booking MVP consisting of a React (Vite + TypeScript) SPA consuming Spring Boot REST APIs. The backend persists Users/Hotels/Bookings in an H2 database via Spring Data JPA. JWT is issued by Auth APIs and attached to subsequent requests to protected Booking APIs.
### Application Layers
- **Client/Presentation:** React SPA (pages, components, routing, API client)
- **API Layer:** Spring Boot REST Controllers
- **Business Layer:** Service classes implementing rules (auth, hotel search, booking overlap prevention)
- **Persistence Layer:** Spring Data JPA Repositories
- **Security Layer:** Spring Security + JWT filter + password hashing (BCrypt)
- **Database Layer:** H2 (in-memory or file mode for local)
### Component Interactions
- React uses an `ApiClient` to call REST endpoints.
- Auth endpoints return JWT; React stores token (localStorage for MVP) and attaches it as `Authorization: Bearer <token>`.
- Booking APIs require JWT; backend resolves authenticated user from token and enforces ownership.
- BookingService checks overlap via BookingRepository query before saving.
### Authentication Flow (JWT)
1. User registers (`/auth/register`) → password hashed → user stored.
2. User logs in (`/auth/login`) → credentials verified → JWT issued (subject = userId/email, claims = roles, expiry).
3. React stores JWT and sends it on subsequent requests.
4. Spring Security filter validates JWT, loads user, sets `SecurityContext`.
5. Controllers access authenticated principal; BookingService uses it to scope data to the user.
### Request Flow (Text Diagram)
```text
User (Browser)
↓
React Frontend (Vite + TS)
↓ HTTPS/HTTP REST (JSON)
Spring Boot REST API (Controllers)
↓
Security Layer (Spring Security + JWT Filter)
↓
Business Services (AuthService / HotelService / BookingService)
↓
Persistence (Spring Data JPA Repositories)
↓
H2 Database (Users, Hotels, Bookings)
```

## 2. High Level Design (HLD)
### 2.1 Presentation Layer (React)
- **Responsibilities**
- Render UI pages: login/register, hotel listing/details, booking creation, booking history
- Manage client-side routing and state (JWT token, user session)
- Call backend REST APIs and display results/errors
- **Inputs**
- User interactions (form inputs, clicks)
- API responses (hotels list, booking confirmation, errors)
- **Outputs**
- REST requests to backend
- Rendered UI and navigation
### 2.2 Business Layer (Spring Services)
- **Responsibilities**
- Auth logic: registration, password hashing, login validation, token creation
- Hotel catalog logic: search, fetch by id
- Booking logic: create booking, enforce overlap rule, list user bookings
- **Inputs**
- DTOs from Controllers (RegisterRequest, LoginRequest, BookingCreateRequest)
- Authenticated user context (principal/userId)
- **Outputs**
- Domain results (User, Hotel, Booking)
- Exceptions mapped to HTTP responses (400/401/409/404)
### 2.3 Persistence Layer (Repositories)
- **Responsibilities**
- CRUD operations on Users, Hotels, Bookings
- Query support (hotel search, booking overlap detection, booking history)
- **Inputs**
- Entity objects and query parameters
- **Outputs**
- Persisted entities, query results
### 2.4 Security Layer (Spring Security + JWT)
- **Responsibilities**
- Authenticate requests via JWT validation
- Authorize access to protected endpoints (Bookings)
- Secure password storage (BCrypt)
- **Inputs**
- HTTP headers (Authorization)
- User credentials (login)
- **Outputs**
- SecurityContext principal
- 401/403 responses when unauthorized/forbidden
### 2.5 Database Layer (H2)
- **Responsibilities**
- Store users/hotels/bookings
- Enforce referential integrity (FKs)
- **Inputs**
- SQL generated by JPA / seed data (data.sql)
- **Outputs**
- Persisted records for app queries

## 3. Low Level Design (LLD)
### 3.1 Frontend Components (React + TS + Vite)
#### Pages (Route-level)
- `LoginPage`
- Form: email, password
- Calls `POST /auth/login`
- Stores JWT and redirects to `/hotels`
- `RegistrationPage`
- Form: name, email, password
- Calls `POST /auth/register`
- Redirect to login on success
- `HotelListingPage`
- Search box
- Calls `GET /hotels?query=...`
- Renders list of `HotelCard`
- `HotelDetailsPage`
- Fetches `GET /hotels/{id}`
- Shows details + “Book” CTA
- `BookingPage`
- Inputs: check-in date, check-out date
- Calls `POST /bookings` (JWT required)
- `BookingHistoryPage`
- Calls `GET /bookings` (JWT required)
- Lists bookings + optional cancel (future; not in current API list)
#### Shared Components
- `NavBar` (links: Hotels, Booking History, Logout)
- `HotelCard` (name, location, short description, View/Book buttons)
- `ProtectedRoute` (redirect to login if no JWT)
- `ApiClient`
- Adds base URL
- Adds `Authorization` header when token exists
- Centralizes error handling (401 => logout)
#### Frontend State
- `AuthContext`
- `token`, `isAuthenticated`, `login()`, `logout()`
- Storage: `localStorage` for MVP (documented limitation)
---
### 3.2 Backend Components (Spring Boot)
#### Controllers
- `AuthController`
- `POST /api/auth/register`
- `POST /api/auth/login`
- `HotelController`
- `GET /api/hotels`
- `GET /api/hotels/{id}`
- `BookingController`
- `POST /api/bookings` (protected)
- `GET /api/bookings` (protected)
- `DELETE /api/bookings/{id}` (protected) — included per required API list; implement cancellation as delete (soft delete recommended)
#### Services
- `UserService`
- create user, lookup by email, validate uniqueness
- `AuthService`
- register, authenticate, build JWT response
- `JWTService`
- generate token, validate token, extract subject/claims, expiry handling
- `HotelService`
- search hotels, fetch hotel by id
- `BookingService`
- create booking for user
- enforce overlap prevention
- list bookings for user
- cancel/delete booking (ownership enforced)
#### Repositories (Spring Data JPA)
- `UserRepository`
- `Optional<User> findByEmail(String email)`
- `boolean existsByEmail(String email)`
- `HotelRepository`
- `List<Hotel> findByNameContainingIgnoreCaseOrCityContainingIgnoreCase(String name, String city)` (or custom query)
- `BookingRepository`
- `List<Booking> findByUserId(Long userId)`
- Overlap query (example): find bookings for hotel where `(checkIn < :checkOut) AND (checkOut > :checkIn)` and status active
#### Authentication Components
- `SecurityConfig`
- Permit: `/api/auth/**`, `/api/hotels/**`, H2 console (optional)
- Secure: `/api/bookings/**`
- `JwtAuthenticationFilter`
- Reads Authorization header, validates token, sets authentication
- `PasswordEncoder` (BCrypt)

- `Hotel (1) ─── (M) Booking`

## 5. API Design
Base path: `/api`
Auth header for protected endpoints:
`Authorization: Bearer <jwt>`
### 5.1 POST /auth/register
- **Purpose:** Create a new user account
- **Request (JSON)**
```json
{
"name": "Jane Doe",
"email": "jane@example.com",
"password": "P@ssw0rd!"
}
```
- **Response**
- **201 Created**
```json
{
"id": 1,
"name": "Jane Doe",
"email": "jane@example.com"
}
```
- **400 Bad Request** (validation)
- **409 Conflict** (email already exists)
### 5.2 POST /auth/login
- **Purpose:** Authenticate user and issue JWT
- **Request (JSON)**
```json
{
"email": "jane@example.com",
"password": "P@ssw0rd!"
}
```
- **Response**
- **200 OK**
```json
{
"token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
"tokenType": "Bearer",
"expiresIn": 3600,
"user": {
"id": 1,
"name": "Jane Doe",
"email": "jane@example.com"
}
}
```
- **401 Unauthorized** (invalid credentials)
### 5.3 GET /hotels
- **Purpose:** List/search hotels from seeded catalog
- **Request**
- Query param (optional): `query`
- Example: `GET /api/hotels?query=beach`
- **Response**
- **200 OK**
```json
[
{
"id": 1,
"name": "Sea View Resort",
"city": "Goa",
"country": "India",
"pricePerNight": 4500.0
}
]
```
### 5.4 GET /hotels/{id}
- **Purpose:** Fetch hotel details by id
- **Request**
- Path param: `id`
- **Response**
- **200 OK**
```json
{
"id": 1,
"name": "Sea View Resort",
"city": "Goa",
"country": "India",
"description": "Beachfront resort...",
"pricePerNight": 4500.0
}
```
- **404 Not Found**
### 5.5 POST /bookings (Protected)
- **Purpose:** Create a booking for the authenticated user
- **Request (JSON)**
```json
{
"hotelId": 1,
"checkIn": "2026-08-01",
"checkOut": "2026-08-05"
}
```
- **Response**
- **201 Created**
```json
{
"id": 100,
"userId": 1,
"hotelId": 1,
"checkIn": "2026-08-01",
"checkOut": "2026-08-05",
"status": "CONFIRMED",
"createdAt": "2026-07-22T10:20:30Z"
}
```
- **400 Bad Request** (invalid dates: checkOut <= checkIn)
- **401 Unauthorized**
- **404 Not Found** (hotel not found)
- **409 Conflict** (overlapping booking)
### 5.6 GET /bookings (Protected)
- **Purpose:** Get booking history for authenticated user
- **Request:** none
- **Response**
- **200 OK**
```json
[
{
"id": 100,
"hotelId": 1,
"hotelName": "Sea View Resort",
"checkIn": "2026-08-01",
"checkOut": "2026-08-05",
"status": "CONFIRMED"
}
]
```
- **401 Unauthorized**
### 5.7 DELETE /bookings/{id} (Protected)
- **Purpose:** Cancel/delete a booking (MVP uses delete; recommended to soft-cancel via status)
- **Request**
- Path param: `id`
- **Response**
- **204 No Content**
- **401 Unauthorized**
- **403 Forbidden** (trying to cancel someone else’s booking)
- **404 Not Found**

## 6. Database Design (H2)
### 6.1 Users Table
**Table:** `users`
- **Columns**
- `id` BIGINT (PK, auto)
- `name` VARCHAR(100) NOT NULL
- `email` VARCHAR(150) NOT NULL UNIQUE
- `password_hash` VARCHAR(255) NOT NULL
- `role` VARCHAR(30) NOT NULL DEFAULT 'USER'
- `created_at` TIMESTAMP NOT NULL
- **Primary Key:** `id`
- **Relationships:** `users (1) -> bookings (many)`
### 6.2 Hotels Table
**Table:** `hotels`
- **Columns**
- `id` BIGINT (PK, auto)
- `name` VARCHAR(150) NOT NULL
- `city` VARCHAR(100) NOT NULL
- `country` VARCHAR(100) NOT NULL
- `description` VARCHAR(1000) NULL
- `price_per_night` DECIMAL(10,2) NOT NULL
- `created_at` TIMESTAMP NOT NULL
- **Primary Key:** `id`
- **Relationships:** `hotels (1) -> bookings (many)`
### 6.3 Bookings Table
**Table:** `bookings`
- **Columns**
- `id` BIGINT (PK, auto)
- `user_id` BIGINT NOT NULL (FK -> users.id)
- `hotel_id` BIGINT NOT NULL (FK -> hotels.id)
- `check_in` DATE NOT NULL
- `check_out` DATE NOT NULL
- `status` VARCHAR(30) NOT NULL DEFAULT 'CONFIRMED' *(e.g., CONFIRMED, CANCELLED)*
- `created_at` TIMESTAMP NOT NULL
- **Primary Key:** `id`
- **Foreign Keys**
- `fk_bookings_user (user_id) -> users(id)`
- `fk_bookings_hotel (hotel_id) -> hotels(id)`
- **Relationships**
- Many bookings belong to one user
- Many bookings belong to one hotel
### 6.4 Overlap Rule (Data + Query)
- **Rule:** A new booking conflicts if there exists an active booking for the same hotel where:
- `existing.check_in < new.check_out` AND `existing.check_out > new.check_in`
- Recommend check-out as **non-inclusive** (common hotel booking convention).
